# ADR-0004 · MVP 的身份、恢复与输入可靠性边界

状态：已接受客户端设计（2026-10-29）；当时实现与真机验收尚未开始。2026-10-30 已有验证壳、隔离测试与有限 macOS 原生结果，见[当前验证记录](../09-prototype-validation.md)，尚未完成真实远端产品闭环。首发三网范围由 [ADR-0006](0006-three-overlay-providers.md)更新，其他可靠性规则保持。

## 背景

手机会切网、进入后台并被系统挂起；桌面也会休眠、锁屏、切网或退出。SSH 成功、RPC 收到响应、终端出现画面和 agent 完成任务是不同事实。若把它们混成“连接成功/操作成功”，可能向错误目标发送凭证、重复执行命令或用旧画面做审批。

## 决策

1. **可信后才使用连接。**Route 必须验证预期 host key，再认证并检查 herdr 能力；未验证的快连接不能成为胜者。首次信任、key 变化与凭证重试明确区分。
2. **每代连接隔离旧结果。**每次重连使用本地 generation，每次 observe 使用 epoch；旧结果只能清理，不能覆盖新状态。stream 的取消和关闭可等待且幂等，共享 overlay 不随一个 Host 的取消停止；进程级 node 的生命周期按 provider 单独定义。
3. **普通 RPC 一请求一 channel。**事件与 observe 各自有明确的长连接生命周期；不假设服务端支持客户端自建多路复用。
4. **事件触发权威读取。**订阅确认后读快照；丢事件后重订阅与重读，不冒充离线历史恢复。缓存保留时间与 stale 标记，未知状态不当成空闲。
5. **输入只尝试一次。**不离线排队，不跨重连自动重发；收到写入确认也不代表命令完成。可能发送但没有确认的按键/文本显示“结果未知”，由用户核对终端后再决定；不能把已发内容恢复成未发送草稿。本地尚未发送的草稿可保留，但不自动补发。
6. **默认观察，显式输入。**五端首版均有完整终端；手机以任务辅助为默认层，但必须支持逐键输入、快捷键与 TUI。直接输入与草稿模式分开，IME 组合不发送，避免双入口重复处理。默认不接管共享 PTY，完整输入不自动授予 resize/takeover。MVP 不提供可执行的一键批准按钮；审批场景只做有新鲜上下文的输入辅助，不将屏幕解析当成服务端授权令牌。
7. **挂起与休眠后允许失联。**移动回前台、桌面唤醒或网络恢复时重新验证连接、快照和全量终端帧。最小化不等同进程挂起；首版不依赖后台轮询或保活承诺，后台通知/推送与托盘常驻后置；手机扫码配对已进入首版。
8. **所有积压有上限。**限制连接尝试、channel、帧和输入缓冲；终端无法可靠续接时重建 observe，不能丢一部分增量后继续假装完整。
9. **多终端仍明确单一输入焦点。**首版手机切换标签、桌面可分屏，各视图独立 observe epoch、VT buffer 与 viewport；同一 Host/session/pane 优先复用已有标签，关闭标签不关闭其他标签共享的连接。写入按远端目标串行；切焦点/重连后的旧输入回调不能落到新 pane。隐藏标签可暂停客户端观察，恢复先新 full，不暂停远端 PTY 或承诺全部隐藏标签实时；分屏不自动授予远端 resize 权限。
10. **前台跨 provider 并发是首版能力。**至少验证 Tailscale + EasyTier 同时连接，声明 ZeroTier 支持时另验 TS+ZT、ET+ZT 与三者同开；普通取消/离网不连带终止其他有效 lease。重复虚拟 IP 需底层定向证据，否则拒绝并解释；不扩为任意同 provider 多身份并发。

这些是客户端责任边界，不是上游新 API 或已存在的实现。精确字段、库回调和资源上限在 M0.5 验证后固定，规则本身作为实现与测试依据。

## 首发范围

公开开源产品的首个发布 MVP 以 iOS、Android、Windows、macOS、Linux 为统一目标，包括手工配置 SSH 主机、可信连接、状态看板、完整终端与手机任务辅助、Tailscale/EasyTier 核心能力、ZeroTier 同步集成及生命周期恢复。具体平台须至少通过 Tailscale 与 EasyTier 两条完整链路及其前台并发验收才标核心目标完成；三网五端 15 格与所声明的跨 provider 并发均通过才宣称完整交付。ZeroTier 的未验组合标实验/未支持，不从当前集成目标移除。首版五端均只连接远端 herdr，本机连接后续再加。M1 可先交付直连内部验证版；它不等于已实现本项目的私网接入差异化。

手机扫码配对及五端本地配置的加密导入/导出进入首版，按 [ADR-0007](0007-pairing-and-config-transfer.md)区分资料导入、host key 信任与 SSH 授权。已选一次性主机 helper，经主机端明确确认后添加手机专属公钥并提供撤销方式；产品选择不豁免实际写入时的确认与权限检查。设备私钥/overlay identity 不克隆，导入不自动连接或发送。后台通知/推送 relay、文件/Git、自动配置同步、多设备冲突控制、自动审批与后台长连不进入首发验收；首版不引入云账号或常驻主机 relay。

## 验证要求

M0.5 并行验证协议 fixtures、五端完整终端/逐键输入和 overlay 字节流，以及逐平台的安全存储和打包；后续必须覆盖错误 host key、迟到连接、断线后的未知写入、events_lost、旧帧、取消/泄漏、IME/多行输入与后台/休眠恢复。仅有静态文档、mock、构建成功或某一端演示不足以通过五端发布门槛。共享代码与各平台接口边界见 [ADR-0005](0005-unified-mobile-desktop.md)，三网矩阵与生命周期差异见 [ADR-0006](0006-three-overlay-providers.md)。
