# ADR-0005 · 公开开源的统一移动与桌面客户端

状态：已接受统一产品与平台边界（2026-10-29）；当时尚无实现与平台验收。2026-10-30 的验证壳、云构建与有限 macOS 运行见[当前验证记录](../09-prototype-validation.md)，不构成五端运行支持。原 Flutter 定案重新开放，候选与 A/B 见 [ADR-0001](0001-single-flutter-stack.md)。三网集成与完成标准由 [ADR-0006](0006-three-overlay-providers.md)补充，最终开源许可证待依赖审查后确定。

## 背景

项目范围由移动客户端扩展为面向更多用户公开开源的统一产品，目标是 iOS、Android、Windows、macOS、Linux。桌面 GUI 属于同一项目，不另建一套互不兼容的客户端。

## 决策

采用统一代码库与共享核心，框架待 A/B 定案；Flutter 是手机优先的第一验证候选，Tauri 2 是主要挑战者。共享协议、Host/session 身份、连接恢复、状态仓库、终端帧与输入草稿。五端首版均提供完整终端交互。手机默认使用任务入口和辅助控件，同时支持逐键输入、快捷键、IME 与 TUI；桌面使用侧栏和工作区，并适配硬件键盘、鼠标与窗口尺寸。两种布局执行相同的信任、未知结果和禁止重放规则；首版明确单一输入焦点，不把快捷键发送到非当前目标。

首版支持多个终端标签，手机切换、桌面可分屏；单一输入焦点不代表只能打开一个终端。各视图独立观察与渲染状态，隐藏标签可暂停客户端观察并在新 full 后恢复，不影响远端运行。分屏布局不自动改变共享 PTY 尺寸；前台不同 provider 同时连接主机纳入首版，具体并发门槛见 ADR-0006。

候选框架平台与插件证据集中在[技术栈复评](../06-technology-evaluation.md)。项目支持范围以本仓库实际验收矩阵为准，不能直接照抄框架支持表。

平台差异通过边界清楚的 adapters 实现：overlay 原生字节流、受保护凭据存储、窗口/输入、应用生命周期与打包。接口共享不等于所有平台已经支持；不能把某个 wrapper 的手机实现自动外推到桌面，也不能把应用代码可编译当作原生库已可加载。

手机首版须有无需本项目桌面 GUI 的扫码接入路径；五端保留本地配置并支持加密导出/导入。二维码资料、SSH 授权和可信 host key 分开，配置迁移不复制设备 SSH 私钥或 overlay 身份，不自动连接。已选一次性主机 helper，由主机端明确确认后添加手机专属公钥并提供撤销方式；后台通知后置，不引入云账号/同步服务或常驻主机 relay。具体获取、授权、字段排除与失败路径见 [ADR-0007](0007-pairing-and-config-transfer.md)。

## 桌面与主机的边界

用户已确定首版只连接远端，桌面作为远端 herdr 控制 GUI，经 SSH 连接已验证的远端 Unix socket，并通过远端 CLI observe 观察终端。Windows 客户端不等于支持 Windows 本地 daemon、named pipe 或 WSL；Mac/Linux 客户端也不自动获得管理本机 daemon 的职责。

本机连接后续再加，本地 socket adapter 只保留扩展点，不进入首版 API 或验收。自动安装/启动 herdr、本地 shell 管理与 WSL 编排均不在当前范围。

## 组件与平台差异

- 终端按 [ADR-0001](0001-single-flutter-stack.md)比较 Flutter/`terminal_view` 与 Tauri/xterm.js；统一手机 fixture 通过后再锁定组件，桌面紧随验证。解析基准不代表绘制性能，公开开源也不代表全部依赖许可兼容。
- 终端字体由 App 提供锁定版本与许可的资源，默认一套验证过的 Nerd Font 家族；五端共同验证 PUA/Powerline、CJK/emoji fallback、cell 宽度、光标与 IME。系统装有字体或远端主题能运行均不能代替客户端验收；字体体积与第三方声明纳入发布材料。
- `tailscale` 0.9.0 wrapper 为 POSIX-only，不支持 Windows。Windows 自建 tsnet 桥是验证候选，不等于底层 tsnet 已被否定；通过前 Windows 只能提供清楚标明实际已验组合的预览，不能宣称 Tailscale 能力或五端三网齐备。[tailscale 发布页](https://pub.dev/packages/tailscale/versions/0.9.0)。
- wrapper 的 Linux 持久身份依赖 `secret-tool` 和解锁的 Secret Service；Android 有 API 31+ 门槛。各平台必须公开依赖与失败行为，不把“安全存储”仅写成手机 Keychain/Keystore。

Tailscale 与 EasyTier 为每个正式支持平台的核心必需，ZeroTier 同步集成；三者各自的 5 格及并发限制见 [ADR-0006](0006-three-overlay-providers.md)。不能因替换 UI 平台就把同一 provider 的参考实现当成已移植。

## 逐平台能力矩阵

当前每个单元都是**待验证**，不是支持承诺；“三网内置能力”须展开到 ADR-0006 的 15 格，不能仅在此勾一个总状态。正式发布时把每格改成通过/失败/未执行，关联版本、设备或系统环境及证据；基础能力、Tailscale/EasyTier 核心单网格或两者前台并发未通过，该平台不能标核心正式支持；ZeroTier 单独标明已支持/实验/未支持，不以其未过否定已验核心，但完整三网目标仍未完成。

- iOS、Android、Windows、macOS、Linux 的 native 产物与打包流水线独立；只在测试与签名/安装条件满足的平台发布正式产物。

## 开源交付

公开仓库提供共享源码、原生桥源码或可核验来源、锁定版本、构建步骤、第三方许可声明和分平台安装说明。用户希望衍生改动继续开放源码；最终许可证根据这一方向与实际分发的库、子模块、补丁及静态/动态链接方式审查确定，不自动指定 GPL/AGPL 或作法律保证，本 ADR 不擅自增加 LICENSE。

分发按用户确定的顺序推进：源码与测试渠道先行，再逐步正式上架。测试包仍需对应平台签名/安装条件与许可材料，明确实验能力；进入商店另按目标渠道要求验证，不将源码公开等同于安装包或上架已完成。

构建采用云端 CI 优先：重型 SDK 与 native 工具链放在对应系统 runner，本地按调试需要选装，不要求维护者先准备五端完整环境。此策略不改变 Flutter/Tauri A/B，也不省略签名、安装升级或真机验收；未签 iOS 包不能当作手机测试交付。产物与签名边界见[云端构建与测试分发](../07-build-and-release.md)，主机 helper 仍使用独立的远端 Unix OS/CPU 矩阵。

五端仍是一套产品路线与版本语义；可以按平台/provider 记录实验进度，但不能将部分组合完成写成“全平台三网同能力”。未完成的平台保留明确阻断项与下一次验证入口。
