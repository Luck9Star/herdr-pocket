传输三条路的取舍（这是整个方案的骨架）

路径怎么做主机依赖优点代价
A. SSH streamlocal
Heeler / 本方案		SSH 开 direct-streamlocal@openssh.com channel 指向 ~/.config/herdr/herdr.sock已有 herdr / sshd、转发权限与 socket 权限不增加常驻转发器；仍需正确 SSH 信任、身份认证与主机权限服务器必须允许相应转发；普通 RPC 每请求新开 channel，不在同一 socket 自行复用
B. SSH exec + 主机脚本ssh host socat - UNIX-CONNECT:… 或每次发一段 python muxsocat / python3兼容老 SSH 库依赖主机工具链；每请求一次进程启动
C. 主机 relay常驻 Bun/Go 进程把 socket 翻成 HTTPS + WS常驻服务 + 端口便于集中提供文件、git、多设备能力；PWA 可连接多一层攻击面和运维；要自己解决公网可达（tailscale serve / CF tunnel / WebRTC）

03各自的设计取向：一句话读一个产品

Heeler · 「agent 控制台，顺便带终端」

终端是二级页。三网络 glue、pump 与生命周期已有源码，可按具体许可移植；Swift / iOS 原生产物须适配所选客户端框架与其他平台。EasyTier wrapper 另有 LGPL 义务。

Kelpie · 「不做抽象，把 herdr 铺上去」

放弃原生看板，直接把 herdr TUI 当终端画面。手机上的信息密度和手势体验依赖 herdr 自己的窄屏布局。

herdrup · 「pane 和 agent 是 UI 对象，不是像素」

这句话直接否掉了通用 SSH 终端路线。代价是必须紧跟 herdr JSON API 演进，且推送要 fork 服务端。

Sherpr · 「不要云、不要推送服务」

通知在设备上从 SSH 事件流生成，前台服务保活，语音用端上 whisper.cpp。减少云侧通知依赖；实际耗电和后台行为需按平台验证。

wooloo / Herdroid · 「Compose 原生，先做能用」

小而完整：spaces → agent → 终端的经典三层。适合作为 Android 端的 UI 参照物。

herdr mobile (tuan3w) · Flutter 参考路径

提供 Flutter + isolate 的参考。原记录称其使用 python mux，选择原因未核实；dartssh2 在 2.14.0 已加入 streamlocal。

Herdr Mobile (benkraus) · 「用 relay 换跨平台」

RN + 主机 relay 让两端 UI 基本一致，原记录列出文件、diff、只读设备等功能。但它把「内网可达」外包给了系统 Tailscale，正是你要补的那块。

Collie / Ovis / 0cv / Roamgate · 「手机只是显示器」

都把重活放主机：轮询、桥接、WebRTC 网关。浏览器侧可免安装、跨端一致；坏处是普通浏览器不能直接运行原生 overlay；主机 bridge 仍可提供 herdr 的实时终端帧。

Moshi · 「把 herdr 当 tmux 之上的一个能力」

商业终端的思路：workspace 级 picker、锁屏事件直达 tab、快捷键前缀对齐。值得抄的是「事件 → 精确位置」的跳转语义。

04当前设计决策

框架候选与共用协议

Flutter 是第一验证候选，Tauri 2 + xterm.js + Rust 是手机终端 A/B 主要挑战者。五端首版只连接远端主机；SSH streamlocal、observe 与原生桥接不是 Flutter 独占，最终框架待实证。

三种内置网络

Tailscale、EasyTier、ZeroTier 都进入集成目标；每端正式支持至少通过 TS+ET，完整三网逐格验收。Heeler 的 iOS 桥是参考来源，非五端现成 SDK；系统 VPN 不计作内置支持。

可信连接

收到 host key 不代表连接获胜。必须完成预期主机身份验证、认证与目标 session 能力检查，失败分支释放资源。身份异常不可自动换密钥。

可靠输入

observe 只负责显示。输入绑定明确目标并由用户发送；写入结果未知时不自动重放，不把 SSH 成功或终端回显当成任务完成。

状态恢复

断线后缓存标为过期；重新订阅并读取权威快照。事件用于触发重读，不能当作可重放的完整日志。首版提供前台状态，后台通知后置，不承诺后台常连。

手机先行、五端分别验证

五端首版均有完整终端，手机增加任务入口与输入辅助；相同真机与 fixture 先验证逐键、IME、触控、Nerd Font、TUI 和恢复，再比较性能。衍生改动继续开源的立场已定，具体许可证经依赖审查后确定。

框架依据见 技术评估；详细契约以 架构文档、ADR-0004、ADR-0005 与 ADR-0006 为准，此页不复制接口定义。

05里程碑

构建采用云端 CI 优先、本地轻量：三网 native 基础产物、五端 GUI 与 Unix 主机 helper 分层，下载测试包后仍须真机/目标系统验收。构建、自动化、签名、分发与运行结果分开，源码与重建材料保留。2026-10-29 比较基线尚无工作流或安装包；2026-10-30 已有实际测试 CI、候选包与有限 macOS 运行记录，不能据此宣称正式发布或五端设备验收通过。规则见 构建与发布，实际结果见 验证记录。

M0.5 先做手机终端 A/B，Windows 原生桥同步验证，再完成多标签/桌面分屏、五端终端及三网络字节流验证。三网共 15 个单网格，另验前台跨 provider 并发；正式平台至少通过 TS+ET 单网与二者并发。手机扫码（手动兜底）及本地加密配置迁移进入 M1，通知与文件后置，不引入云账号/自动同步。阶段与验收统一维护在 路线图，不把旧工期估算当交付承诺。

06证据与许可

2026-10-29 复核已确认 dartssh2 的自定义 SSHSocket / streamlocal 接口、herdr 的 observe 与事件恢复规则；未执行本项目真机集成。历史竞品矩阵没有逐项重新复核。

可以按许可复用 Heeler 代码：根 Apache-2.0 不覆盖全部 native 组件，EasyTier wrapper 为 LGPL-3.0-or-later，需对应源码及重构建 / 安装等资料。已核对的 libzt 版本于 2026-01-01 转为 Apache-2.0，ZeroTierOne core 及补丁仍须保留 MPL 等义务。实际分发物逐项核对，不凭开源或 BSL 标签直接判定。

其他 App 的发布记录不能证明本项目必然获批；本轮未确认历史记录中的商店状态。源码与测试渠道先行、逐步正式上架的节奏已定，仍须满足签名、安装与平台规则；具体许可证经依赖审查后确定。发布前补齐源码构建、依赖声明、逐平台支持与产物来源，不能把开源仓库等同于五端可安装产品。
