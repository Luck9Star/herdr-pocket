传输三条路的取舍（这是整个方案的骨架）

路径怎么做主机依赖优点代价
A. SSH streamlocal
Heeler / 本方案		SSH 开 direct-streamlocal@openssh.com channel 指向 ~/.config/herdr/herdr.sock无（只要 AllowStreamLocalForwarding）零安装、隐私最好、延迟最低、不需要额外鉴权层服务器禁用 socket 转发就废；一次连接只服务一个请求，要自己做多路复用
B. SSH exec + 主机脚本ssh host socat - UNIX-CONNECT:… 或每次发一段 python muxsocat / python3兼容老 SSH 库依赖主机工具链；每请求一次进程启动
C. 主机 relay常驻 Bun/Go 进程把 socket 翻成 HTTPS + WS常驻服务 + 端口功能最丰富（文件、git、多设备）；PWA 也能用多一层攻击面和运维；要自己解决公网可达（tailscale serve / CF tunnel / WebRTC）

03各自的设计取向：一句话读一个产品

Heeler · 「agent 控制台，顺便带终端」

把「谁在等你」做成主界面，终端是二级页。所有复杂度压在传输与穿透层（libssh2 + 三个 userspace 网络栈），UI 保持极简。可移植性最好：Apache-2.0、ADR 写得像教科书。

Kelpie · 「不做抽象，把 herdr 铺上去」

放弃原生看板，直接把 herdr TUI 当终端画面。开发成本最低，但手机上的信息密度和手势体验全靠 herdr 自己的窄屏布局。

herdrup · 「pane 和 agent 是 UI 对象，不是像素」

这句话直接否掉了通用 SSH 终端路线。代价是必须紧跟 herdr JSON API 演进，且推送要 fork 服务端。

Sherpr · 「不要云、不要推送服务」

通知在设备上从 SSH 事件流生成，前台服务保活，语音用端上 whisper.cpp。隐私最彻底，代价是 Android 专属、耗电、iOS 走不通。

wooloo / Herdroid · 「Compose 原生，先做能用」

小而完整：spaces → agent → 终端的经典三层。适合作为 Android 端的 UI 参照物。

herdr mobile (tuan3w) · 「Flutter 已验证可行，但传输笨」

唯一先例证明 Flutter + isolate 能跑 herdr。它没享受到 dartssh2 4.x 的 streamlocal，才用 python mux 脚本补，这点你不要继承。

Herdr Mobile (benkraus) · 「用 relay 换跨平台」

RN + 主机 relay 让两端 UI 基本一致，功能也最全（文件、diff、只读设备）。但它把「内网可达」外包给了系统 Tailscale，正是你要补的那块。

Collie / Ovis / 0cv / Roamgate · 「手机只是显示器」

都把重活放主机：轮询、桥接、WebRTC 网关。好处是零安装、跨端一致；坏处是永远做不到自带穿透，且实时终端要么轮询要么另造帧协议。

Moshi · 「把 herdr 当 tmux 之上的一个能力」

商业终端的思路：workspace 级 picker、锁屏事件直达 tab、快捷键前缀对齐。值得抄的是「事件 → 精确位置」的跳转语义。

4.3 穿透层的真实工程细节（Flutter 特有的坑）

Heeler 在 Swift 里能把 overlay dial 出来的 fd 直接交给 libssh2。Dart 没有 Socket.fromFd，所以有两条等效路径：

A. 实现 SSHSocket（推荐）

dartssh2 的传输层接受自定义 SSHSocket（stream + sink）。用 FFI 调原生节点的 read/write，包成一个 Stream/Sink 交给 SSH 层。没有本地端口、没有额外拷贝，语义最接近 Heeler。

B. 回环监听

原生侧在 127.0.0.1 开一个 listener 转发到 mesh 目标，Dart 侧正常连 localhost。实现最省事，但多一次拷贝、要管端口生命周期和本地暴露面。

选 A；A 的阻塞读写必须放在 isolate 里，否则掉帧。三个 overlay 共用同一个 OverlayNode 契约：

abstract class OverlayNode {
  OverlayKind get kind;
  Future<void> start();
  Stream<OverlayStatus> get status;          // 在线 / 直连或中继 / 延迟 / 对端列表
  Future<HerdrSocket> dial(String host, int port);  // 返回可直接当 SSHSocket 用的字节流
  Future<void> stop();
}

4.4 Host / Route 竞速（照抄 ADR-0022 的设计，别自己发明）

Host { name, user, auth, session, routes[] }
Route { address, port, jump?, overlayId? }

连接时：
  直连 Route        → 立刻发起
  overlay / jump Route → 延迟 400ms，或所有直连都失败时立刻
  先握到 host key 的赢 → 取消其余
  host key 信任绑在 Host 上（不是地址）→ 换网络不误报

为什么重要：同一台机器在家走 LAN、在外走 tailnet。不做竞速，就要么每次等超时，要么让用户手动切地址。Heeler 把这套写进了 ADR，直接按它的语义实现即可。

05里程碑与验收标准

阶段内容验收（必须真的跑出来）估时
P0先用现成方案跑一周（Collie 或 Ovis + 系统 Tailscale）能列出「我每天真正用到的 5 个动作」，确认不是 UI 焦虑0.5 天
P1协议层：Dart 侧 SSH streamlocal + JSON RPC + observe 帧 → 命令行 demoLinux 上 dart run 能列出 agent、打印实时终端字节、发文本并看到回显3–5 天
P2Flutter UI 最小闭环：多机 → 看板 → 终端 → 输入真机（iOS + Android）上 60fps 滚终端，打字不丢键1–2 周
P3Overlay：先 Tailscale（tsnet），再 EasyTier（Rust no-TUN）关掉系统 VPN，仅靠 App 内节点连上 CGNAT 后的主机2–4 周
P4配对插件 + FCM/APNs 中继扫码 30 秒配对成功；手机锁屏能收到 blocked 通知并直达对应 pane1–2 周
P5Route 竞速、文件/预览、diff、生物锁、多语言换网络不重配；断线 5 秒内自愈按需

粗略总量：单人 + AI 助手，做到「自己每天能用」约 6–8 周；做到「能给别人用」再加 4–6 周（签名、审核、崩溃上报、i18n、更新通道）。

6.2 未核实 / 必须在开工前打掉的假设

  1. package:tailscale 在 iOS 静态链接 + 后台切换下的真实表现（0.9.0，下载量低）。→ 先写 200 行 spike。
  2. libghostty 的 Android 支持：没找到可靠结论，所以按 xterm3 估；如果终端体验是核心，双原生 + 共享 Rust core 的上限更高。
  3. userspace 网络栈的耗电与 Doze 存活：没有公开实测。Android 需要前台服务或 WorkManager 保活策略。
  4. iOS 审核对「App 内自带 userspace VPN」的态度：Heeler 已上架说明走得通，但它是把 overlay 作为可选功能；宣传口径别写成「VPN」。
  5. herdr 插件生态的 API 还在演进（plugin v1 无原生 UI 注册），配对/推送插件要跟着 min_herdr_version 走。
  6. Play 上的 dev.herdr.mobile 与 benkraus 仓库的对应关系是「包名一致」推断，未 100% 核实。
一句话建议。先做 P1（协议层）——它是整件事里唯一「一次投入、两端复用、且不依赖任何第三方库成熟度」的部分。协议层跑通后，UI 用 Flutter 堆是体力活，穿透是分包活。 反过来，如果先做 UI，八周后你手里会是一个和 Sherpr 差不多、但少了 token 的安卓 App。
证据来源：本机 herdr 0.9.5 实测（terminal session observe 帧格式、herdr api schema、socket 路径）；各项目 README / docs/adr（Heeler ADR-0011/0021/0022、benkraus relay 架构）；gh search code 核实 dartssh2 / russh 的 streamlocal 支持；各仓库许可证字段。未核实项已在 6.2 单列。
