# Android EasyTier candidate build

The explicit-batch `Android network candidate batch (arm64)` workflow builds the pinned Heeler/EasyTier source and the portable managed-node patch for Android API 35 and arm64-v8a. It uses the existing lock, source, and patch verification in `portable_candidate.py`; the native build uses Rust 1.95 and NDK 28.2.13676358. GUI Rust uses 1.96. Both GUI jobs consume the same workflow run's native artifact after verifying its checkout commit, hashes, ELF architecture, required exports, and dynamic dependencies. Flutter explicitly enables `network-easytier`; Tauri passes the same feature to its Android build. The default GUI builds do not enable it.

The native artifact contains the actual shared library, upstream source archives at their locked commits, locks, portable patch and source, license files, build logs, provenance, and SHA-256 manifest. App artifacts contain the APK, hash, native manifest, and report. APK verification checks arm64-only native entries, identical bundled Heeler bytes, and the app library's dynamic dependency on Heeler. Materials support rebuilding and license review; their presence is not a completed LGPL or distribution compliance assessment.

This workflow is experimental and has not been run as part of this change. A successful future run would establish compilation and static inspection only. Android dynamic loading, installation, real-device behavior, node startup, and network connectivity remain separate, untested claims. No fixture or credentials are used. Native build failures fail the dependent jobs, with logs uploaded where available. The independent baseline workflows remain unchanged in their ABI and feature choices.

To run one reviewed batch without merging product code into main, push its commit to a fresh `codex/network-batch/<batch-name>` branch. This prefix does not match the existing `codex/batch/**` pipeline, and ordinary `codex/core-prototype-validation` pushes do not trigger it. No such branch was pushed in this change. `workflow_dispatch` is retained for use after registration on the default branch; it is not assumed available from this prototype branch alone. See the [official trigger rules](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows). Both jobs check out the triggering SHA; native and APK artifacts retain 14 days and are not Releases.
